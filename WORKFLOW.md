# Workflow

## Operating Model

This project uses:

- Notion for product/strategy/docs
- Linear for execution tracking
- GitHub for code truth

## Role Split

### Founder / Product Owner

Owns:

- product direction
- priorities
- pricing
- trust/privacy stance
- launch decisions

### Implementation Engine

Owns:

- code changes
- migrations
- schemas
- APIs
- UI implementation
- debugging
- validation

### Strategy / Architecture Support

Owns:

- PRDs
- tradeoff analysis
- ranking/filtering design
- architecture thinking

### Research Support

Owns:

- competitor research
- market facts
- pricing benchmarks
- sourced inputs

## Weekly Rhythm

### Monday

- review roadmap and decisions
- define weekly goal
- move priorities into Linear
- assign clear tasks

### During the Week

- track active work in Linear
- land code via GitHub
- update docs only when decisions change

### Friday

- summarize shipped work
- capture decisions and learnings
- note risks/blockers
- define next week's priorities

## Delivery Rules

- keep inherited scrape/parse flow stable first
- do not redesign everything at once
- use focused PRs
- avoid mixing infra, parser, and product logic changes unnecessarily
- document decisions that change architecture or scope

## Milestone Sequence

1. Acquired Core Baseline
2. Extension Architecture
3. V1 Ranking + Filtering
4. Private Alpha
5. Shared Corpus Decision
6. Launch Candidate
